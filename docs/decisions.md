# Decisions

What was chosen for this workspace, and why.

| Topic                    | Decision                                                                                                                                                    | Why                                                                                                                                                                                                                                                                                                                                                                        |
| ------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Starting point           | Began as a scrubbed derivative of an internal, design-constrained proof of concept, which itself began from `myvictorlife/base-angular-monorepo` (MIT; notice kept in `THIRD_PARTY_NOTICES.md`) | Standalone, zoneless Angular with lint-enforced boundaries, i18n, tests and Storybook already in place                                                                                                                                                                                                                                                                    |
| Domain                   | None. fungular is deliberately neutral — no product entity, no learner/LMS concepts, no client-specific branding                                              | It is a playground: the interesting parts are the architecture, the mock API, the hosting story and the analytics integration, not the domain                                                                                                                                                                                                                                |
| Theming                  | Neutral Tailwind-palette tokens in `libs/theme/src/styles/_tokens.scss`; **dark mode enabled** (`$dark-palette-enabled: true`); no design-token catalogue page | One theming seam: brand colours are inline `--color-*` variables on top of it, and surfaces/text stay theme-controlled so brands read identically in light and dark                                                                                                                                                                                                          |
| Demo brands              | Three **fictional** tenants (`Solstice`, `Harbor`, `Meadow`) as JSON under `apps/demo-app/src/assets/brands/`, applied at runtime by `BrandThemeService`; selecting a tenant is selecting a theme, so the moot barns and the data swap together                    | Shows runtime theming without any real-brand or design-system constraint; the JSON is the swap point for a real branding source later                                                                                                                                                                                                                                       |
| Auth                     | Fake sign-in (`POST /api/auth/login`): any `@example.com` email works; `single@example.com` belongs to one tenant, everything else to three. `SessionStore` (root-provided by design) + `guestOnlyGuard`/`requireAuthGuard`/`requireTenantGuard`; session persisted to localStorage; tenant sent to the API via the `X-Tenant-Id` interceptor | Multi-tenant is the demo's spine — login → chooser → workspace-scoped data — and the auth machinery is the swap point for a real backend later                                                                                                                                                                                                                                |
| Session lib              | **Eager**, not lazy: loaded with the app bundle because the root store, guards and interceptor must exist before any page | The `loadChildren`-only rule is for feature libs; auth is app chrome. Documented in `app.routes.ts`                                                                                                                 |
| Coverage floors          | New feature lib floors track *just under* what the projects measure today (pages are exercised by Playwright, not unit specs) | Same convention as the origin — floors are a tripwire, not a badge; they rise as unit coverage does                                                          |
| Backend                  | None. A **Cloudflare Pages Function** (`functions/api/[[path]].ts`) answers `/api/*` with a table of mock handlers — same-origin, so the app calls plain `/api` URLs                                                                     | Mock data belongs on the edge, not in the browser: one implementation serves local (`wrangler pages dev`) and production, and is the swap point for a real Worker/backend later. The e2e suite runs against this stack                                                                                          |
| State                    | NgRx **SignalStore** per feature, provided on the route; the global store carries router state only                                                         | Classic actions/effects are not used by the workspace                                                                                                                                                                                                                                                                                                                     |
| Analytics                | Vendor-neutral `ANALYTICS` token with `NoopAnalytics` default; a vendor implementation goes in its own `analytics-<vendor>` lib, loaded with a dynamic `import()` | Call sites never know the vendor; swapping PostHog for Plausible or nothing is one provider in `app.config.ts`. PostHog is the first planned implementation                                                                                                                                                                                                                |
| Static hosting readiness | Fonts and the font stylesheet load by relative URL (`public/fonts/fonts.css`); SPA fallback via `_redirects` (`/* /index.html 200`) and Pages Functions before it | Absolute `/fonts/*` URLs break under a sub-path base href; deep links verified in a browser                                                                                                                                                                                                                                                                               |
| Hosting                  | **Cloudflare Pages** (free): build `npm ci && npx nx build demo-app --configuration=production`, output `dist/apps/demo-app/browser` (`wrangler.toml`), SPA fallback + Pages Functions mock | Free, unlimited bandwidth suits a public playground; the mock API runs as Pages Functions on the same project; per-PR preview deployments; `wrangler pages dev` reproduces production locally                                                                                                                                                                              |
| Config pipeline          | The template's `config/*.json` → generated TypeScript pipeline is ported back for integrations; a clone ships with integrations disabled                       | No credentials in git, ever; a public repo's clones must never report into the owner's analytics project                                                                                                                                                                                                                                                                   |
| Dependency overrides     | `undici` is overridden to 7.30.2                                                                                                                            | Nx 23.3.1 pins 7.29.0, which has DoS, response-splitting and TLS-bypass advisories. Drop the override once Nx ships a patched pin                                                                                                                                                                                                                                            |
| Dependency updates       | Dependabot (`.github/dependabot.yml`), weekly, grouped by framework set                                                                                     | Built into GitHub, so no third-party app gets access to the code. No lock-file maintenance equivalent: run `npm run deps:relock` periodically                                                                                                                                                                                                                               |
| CI npm cache             | Written by `main` pushes only (`actions/cache/restore` + `save`); PRs restore it, and `cache-cleanup.yml` deletes a PR's caches when it closes              | The key includes the lockfile hash, so every lockfile change created a ~200 MB entry per PR. A PR cache is unreadable by other PRs and dead once merged                                                                                                                                                                                                                     |
| Storybook on Vite        | `@storybook/angular-vite` (preview until Storybook 11), with `@analogjs/vite-plugin-angular` and `vite` as direct devDependencies                           | The Webpack framework `@storybook/angular` requires the deprecated `@angular-devkit/build-angular`. Angular's own Vite use is limited to its dev-server builder and exposes no plugin, so the Vite framework compiles components with Analog's plugin, a required peer. Fallback: `@storybook/angular` + `build-angular`                                                     |
| Accepted audit findings  | Dev-only findings remain; 0 in the production tree (`npm audit --omit=dev` is clean)                                                                         | Every remaining finding is the `minimatch` 10 chain dragged in by Nx/typescript-eslint, fixed only in 11. Revisit when those upstreams move                                                                                                                                                                                                                                   |
| Supported browsers       | `browserslist` in `package.json` is `baseline widely available` (today Chrome/Edge 124+, Firefox 125+, Safari and iOS Safari 17.4+, Android Chrome/Firefox) | Written down so the policy is a decision, not an Angular default; it is the same query, so output is unchanged and the floor rises on its own                                                                                                                                                                                                                                 |
| TypeScript target / lib  | `target` and `lib` are `es2023` (`dom` kept)                                                                                                                | Every supported browser ships ES2023. `es2024` is held back because its `lib` types `Atomics.waitAsync`, which Firefox and Safari lack. Revisit when the floor moves                                                                                                                                                                                                         |
